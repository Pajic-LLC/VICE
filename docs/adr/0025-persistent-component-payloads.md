# 0025: Persistent generic component payloads (Phase 7, Slice A)

Status: Implemented foundation; subsequent Phase 7 slices remain separate.

## Decision and motivation

World's existing component-type registry gains immutable, versioned field schemas and actual per-entity payloads. A schema has a stable UUID, name, version and numeric field IDs. Each field has one VICE-owned scalar kind: bool, signed int64, finite binary64, printable UTF-8 text, or a non-nil opaque persistent identifier. Names have no engine semantics. Empty schemas may be used as marker components. No game class layout, reflection offsets, executable pointer, third-party type or process-local handle is persisted.

This is deliberately a flat, bounded first substrate. All declared fields are required; each entity has at most one instance of a type. Unknown, duplicate, missing or mistyped fields fail validation. Fields and instances are canonicalized by stable ID; negative real zero is normalized. Text permits quotes/backslashes and printable UTF-8, but not embedded controls/line breaks. IDs are opaque values, not strong entity references: deleting an entity named by an identifier field does not cascade or prevent deletion. The owner and schema identities are checked; typed reference semantics belong in a later extension.

World owns payloads in entity slots and a type-use count index. Removing spatial state, physical solver rebuilds, region/fidelity changes and presentation evaluation do not remove payloads. Entity destruction removes owned payloads and updates the index; recycled entity handles cannot access them. A schema cannot be unregistered while in use. Payloads do no work per frame and remain available in inactive regions. Explicit game writes are permitted in any fidelity; future schedulers/rules will decide when to simulate them.

## Mutation and persistence

`World::set_component` is an atomic, validated whole-payload upsert. Reads return owned values, not mutable access to World internals. `remove_component`, schema lookup and entity payload enumeration complete the initial contract. Schema registration does not redefine an existing type. The SDK additionally treats identical registration as success so native modules can register/verify their schema after loading a save. A different schema/version for that UUID reports `schema_conflict`.

Source `component` records optionally declare `fields`; entity `state` records contain a type UUID, version and typed field values. Explicit kinds make source records independent of declaration order. Revision-safe source transactions can register, set and remove components, validating a complete candidate before publication. Whole-payload writes do not yet provide arbitrary multi-entity runtime transactions or rule effects.

World file v16 adds a bounded schema-fields string to each component-type record and a sparse trailing table of owner UUID plus bounded payload text. Numeric text uses the classic locale and round-trip precision. Schema records retain the previous ID/version/name prefix. Empty Worlds add four bytes; legacy schema entries add five bytes for a zero-field string. Payload records are bounded to 8192 bytes, sufficient for maximum escaped text; other existing string bounds remain unchanged. Readers retain v1–15 compatibility. Unknown wire kinds/versions fail explicitly. Restore constructs and validates a replacement World, then swaps only on success. Invalid restore cannot change the existing World.

Snapshots, binary saves, Runtime checkpoints, standalone Runtime and Editor Play clone/reset all use these same contracts. Editor undo/recreation preserves payloads. Normal source/Runtime inspection exposes `component_payloads`; Runtime also returns the relevant `component_schemas`, and the Inspector displays data and schema names. Existing Runtime `components` presence flags are retained. Debug int64 values are decimal strings with an explicit integer kind so JSON consumers cannot lose precision above 2^53.

ABI 1 appends size-checked fixed-capacity schema/value/data DTOs and callbacks for schema register/read and payload read/set/remove. All old offsets remain unchanged. Native game code owns meaning and interpretation. Callback-phase and owner-thread guards remain enforced; frame callbacks can read but cannot mutate. No STL crosses this boundary. SDK DTOs are transport values, not the persistence format.

## Bounds, cost and evidence

Limits: 16 fields per schema, 16 payloads per entity, 65536 World payloads, 65536 type identities, 128 UTF-8 bytes per text value, 64 ASCII bytes per field name and 128 bytes per structured schema name. Identity-only legacy names retain the file's 4096-byte bound; the SDK schema-name buffer is 128 bytes and refuses larger legacy names. Limits are initial contracts rather than claims of production population throughput.

Persistent owner/type lookups use existing hash maps. Per-owner payload lookup uses a sorted vector: O(log K) comparisons and O(F) copying, with K,F <=16. Mutation validates O(F²) bounded field/name uniqueness and shifts O(K) entries. Schema-use queries/unregister guards are indexed, not full-entity scans. Schema registration retains the existing O(T) name-uniqueness check; registering many schema types is not an entity tick operation. Snapshot/restore visits stored records and sorts canonical entity/type identities. Existing Runtime debug sampling takes a World snapshot, so inspection is O(World size), not a cheap per-frame query.

A slot adds one empty vector (24 bytes on the tested 64-bit build). Each attached payload adds its payload object, field-vector capacity, and any non-inline string allocations. A local Release smoke run measured 40-byte field values and 48-byte payload objects. For 10000 five-field owners, attach took 7.53 ms, copied queries 2.69 ms and validated encode 36.25 ms; the cooked World was 2180193 bytes. These numbers are environment-specific. Measured object sizes, 10000-owner attach/query/encode timings and cooked bytes are captured by `vice_component_payload_tests`; these are CPU smoke measurements, not a frame-time or allocator-resident-memory guarantee. Payload storage has no tick. Render/Editor render, status and profiler read projections omit payload copies; those projections carry an incomplete flag and are rejected by restore/save. Full snapshots remain the default for persistence, Play clones, undo and explicit debugging. If entity memory, schema counts or measured mutation cost become problematic, sparse storage, interned schema metadata or typed columns can replace storage behind these contracts.

Focused tests exercise deterministic bytes/source, all scalar types, maximum escaped text, marker components, invalid UTF-8/nonfinite values/versions, stale handles, duplicate/missing identities, atomic failed restore/source transactions, v15 compatibility, large coordinates and inactive state. SDK tests exercise size/thread/phase guards, old hosts, native module reload, Editor isolation/reset and Inspector access. A real walk/drive/animation/audio example stores game-defined session counters; native checkpoint/restart proves their continuity. Authoring examples named VehicleCondition and AmmoState use the same generic core without adding genre APIs.

## Alternatives and future changes

Raw C++ bytes were rejected for ABI/layout portability. Arbitrary JSON blobs were rejected because schema, types, identities and bounds must be engine contracts. A second game database or Editor-only object model was rejected because restore and tooling must share World truth. An unbounded recursive value tree was deferred until concrete content needs justify arrays/nesting and their wire tags/limits.

Only one schema version per type is active in a World. No automatic migration, defaults, optional fields or reinterpretation is performed. Future migration must operate on a complete validated candidate, preserve type/owner identity and define failure behavior. New field kinds require explicit wire/API version handling. Stateful relations, typed World events with causal provenance, time/scheduler, quantities/transfers, condition/effect rules, agents and replication are not implemented by this decision. This slice makes those subsequent primitives possible without inventing game semantics.

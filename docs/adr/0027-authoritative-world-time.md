# 0027: Authoritative World time for typed event timestamps

Status: Implemented clock prerequisite for Phase 7 Slice C; covers the basic Slice D clock contract. Scheduler is separate.

World owns one simulation clock independent of wall-clock/calendar interpretation. A tick is one microsecond. Its uint64 counter, paused/automatic flags, fixed-point rate, rate remainder and sub-tick input fraction persist in World snapshots and file v18. Readers retain v1–17 support with a zero/default clock. Source `world_clock` records and revision-safe `set_world_clock` edits preserve the same state. Restore validates a replacement World before publication.

Rates use integer milli-scale: 1000 is 1x; allowed rates are 1–1000000 (0.001x–1000x). Fractional scaled ticks carry a remainder modulo 1000, including across rate changes and saves. Integer source-step advancement checks multiplication/addition overflow before mutation. Exact `step_world_clock` adds World ticks directly, independently of pause/rate/automatic, for deterministic stepping and explicit gameplay authority. It cannot rewind. Full snapshot restore/source editing may restore an earlier time; callers must restore coherent associated state.

Automatic Runtime and Editor Play advancement occurs before the game update with the same clamped delta used by the host. Conversion of fractional-second host input preserves sub-microsecond residue in World. Determinism is guaranteed for identical integer inputs/configuration; this is not a claim of deterministic wall-clock playback or lockstep physics. Save/reload preserves the exact published clock and both remainders. Pause freezes the clock's source advancement, not the entire physics/render/audio engine. Editor playback pause additionally stops ordinary updates; explicit stepping still follows the configured World-clock policy. Games may coordinate broader pause behavior.

The append-only ABI exposes copied clock state, configure and exact-step operations under existing size/thread/phase guards. Runtime debugging and Inspector expose ticks/rate/pause; source inspection exposes the complete state. uint64 ticks are decimal strings in JSON to avoid binary64 precision loss. The clock is O(1), global rather than per-region, with no per-entity scans. Reduced/inactive regions share World time; future schedulers will choose which consequences to simulate.

A float-only elapsed counter, wall-clock timestamps, game calendars and per-agent clocks were rejected. Integer storage/rate remainders avoid long-run float accumulation and keep controlled steps reproducible. Fractional host input is a persistence field rather than a process-only approximation. The 64-bit microsecond range supports generic long-duration simulation; a future epoch/calendar representation can extend interpretation without assuming Earth days.

Tests cover fractions, split/resume identity, pause, exact stepping, rate changes, acceleration, overflow/invalid input, source/binary/legacy persistence, native SDK guards and Editor isolation/parity. This prerequisite exists so retained facts and transient signals can share authoritative timestamps without inventing a competing time counter.

# ADR 0028: Typed World facts and transient signals

Status: Accepted for Phase 7 Slice C.

## Decision and invariants

World owns event publication. A game-defined component schema UUID/version is also an event payload type; the engine validates structured values without understanding their names. An event has a required subject, two optional entity references, optional region, origin, authoritative World-clock microsecond timestamp and up to four causal parents. Publication validates live entity/region references, payload and all parents before changing counters or history. Native gameplay modules always publish gameplay origin; engine integrations can supply another origin. Historical references remain valid evidence after entity/region deletion.

Retained facts extend the existing causal journal as `world_event`; physics/dependency evidence and gameplay facts therefore share one lineage, sequence and retention window. Existing physical event validation remains strict. Parent references contain history UUID, event UUID and sequence; they must identify retained records at publication. Parents are unique and sorted by sequence. Every retained parent precedes its child. The oldest parent is mirrored into the legacy single-parent envelope for compatibility; the new query follows every parent. A fact may cite earlier capture segments in the same lineage, including after checkpoint resume. Forked continuations retain old identities and generate distinct new UUIDs. Ordering and serialized published state are deterministic; UUID allocation and wall-clock-driven playback are not claimed to be replay deterministic.

The journal retains its latest 1024 records, including capture markers and physical evidence. A parent may be pruned immediately after validated publication, or later; its UUID/sequence remains in the child, and inspection reports that it is pruned. No unbounded archival history is introduced. Emitting the first retained fact starts capture if needed; later engine changes can be recorded under that same capture policy. Important histories exceeding this window require a future explicit archive/pinning policy, not silently unlimited memory.

Signals use a bounded delivery window (256) and one World-second lifetime. This is ephemeral delivery state, not another authoritative history. Signals can cite retained causal evidence, but cannot themselves be parents. Producers needing causal evidence must choose retained publication. Both modes use the same typed payload validation, identities, clock and World references. A signal stream UUID distinguishes a fresh World/restore from an old cursor. Sequence ordering and explicit first/next counters let consumers detect missed deliveries. Expiry is driven by advancing World time, including manual steps; a paused clock preserves signals until capacity eviction or explicit clear. Clear keeps the stream and sequence range. There are no callbacks, polling agent copies or persisted executable pointers.

## Persistence and failure

World snapshot, checkpoint, save/load, Editor Play clone/reset and standalone Runtime preserve retained facts, schemas, causal references and clock. Signals are deliberately excluded and are never replayed after restore. Region fidelity changes do not discard facts or signal metadata; future consumers decide whether/how to observe them. Region handoff must transfer a coherent World lineage, not detach an independent event database. No distributed merge/replication protocol is implemented.

Snapshot file v19 appends a timestamp and typed-data tag to each causal record; optional typed payload/parents use a bounded 8192-byte structured record. v1–18 readers remain supported with zero timestamps for pre-v19 evidence. Source history records accept `at T` and `typed PAYLOAD PARENTS`; canonical writers emit timestamps. Restore validates the complete candidate World, including schemas, causal DAG, monotonic timestamps and timestamps no later than saved World time, before replacement. Source clock edits cannot rewind below retained facts unless the associated history is coherently replaced. A failed restore/publication leaves state unchanged. Out-of-memory handling follows existing engine allocation policy.

Schema use counts include retained facts and live signals; removal is blocked until their last use expires/prunes. Render-only projections skip the journal entirely and cannot be saved/restored. Inspection exposes payloads, targets, time, parents, retention range and truncation through World/CLI/Runtime debug; the module API exposes copied fixed-size envelopes. The old causal ABI layout is unchanged. Appended size-checked functions handle rich events/signals, with existing callback phase and thread restrictions.

## Performance and alternatives

Sequence lookup and append/evict are O(1), excluding bounded payload work. Parent validation costs at most four indexed reads plus a tiny sort; payloads retain Slice A's 16-field/128-byte-text limits. Signal expiry is O(expired), with no scan of all entities or schedules. Queries scan at most 1024 history or 256 signal entries and return at most 64; multi-parent context traversal is bounded by the query budget. Serialization is O(retained payload size). CausalEvent stores an optional payload plus dynamic bounded field/parent allocations; stress tests print native `sizeof`, retained counts, encoded size and measured throughput. No per-entity/per-frame event evaluation is introduced. The shared retention window means a very noisy producer can evict unrelated evidence; per-type quotas or explicit archives would require a separate policy decision.

A second gameplay journal was rejected because it would split cause identity and inspection. Persisting all signals was rejected because delivery notifications should not replay on load or grow saves. Arbitrary callbacks and process pointers were rejected as unsavable. A new standalone event schema system was rejected in favor of the existing validated structured schema substrate. Signal-to-signal causal chains, unbounded target/parent arrays, configurable retention, subscribers and network replication are deferred until a concrete requirement justifies them. Future agents must receive explicitly authorized observations of these facts; this API does not grant hidden-world knowledge or conflate beliefs with truth.
